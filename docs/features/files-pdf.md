# Files and PDF

## File field representation

A `FileField`/`ImageField` is never serialized as a raw path or URL string. `FileFieldsMixin`
(part of `BaseSerializer`) represents it as a small object instead:

```json
{
  "url": "https://.../media/....png?token=1699999999.abc123...",
  "name": "logo.png",
  "ext": "png",
  "kind": "image",
  "mime_type": "image/png",
  "size": 48213
}
```

`kind` is derived from the file extension (`image`, `pdf`, `video`, `audio`, or `file` as a
catch-all) — not from the actual file content.

## Protected URLs

Every file URL carries a `?token=` query parameter, generated by `FullPath` (HMAC-signed against
`FILE_TOKEN.KEY`) and validated by `FileAccessMiddleware` on any request under `settings.MEDIA_URL`
— see [Middleware](../architecture/middleware.md#fileaccessmiddleware-coremiddlewarefile_accesspy---enabled-by-default).
A token is signed over its expiry **and the URL path it was issued for**, so a token taken from
one file's URL never opens another file. Without a valid token for that exact path, the answer is
`401` in the [error contract](../api/errors-and-alerts.md):

```json
{"error": {"message": "Not authorized", "code": "file_token_invalid", "details": null}}
```

Two kinds of token:

- **Temporary** (the default for any field not listed in the serializer's
  `permanent_fields_files`) — time-limited, `FILE_TOKEN.TEMP_TTL` seconds (default `300`),
  gated by `FILE_TOKEN.ENABLE_TEMPORARY`.
- **Permanent** — for a field name explicitly listed in `permanent_fields_files` on the
  serializer, gated by `FILE_TOKEN.ENABLE_PERMANENT`. Still bound to its file.

```python
class DocumentSerializer(BaseSerializer):
    permanent_fields_files = ["attachment"]   # this field's URL never expires

    class Meta:
        model = Document
        fields = "__all__"
```

Code that returns a file URL outside a serializer (a service payload, an e-mail) signs it the
same way — never return `file.url` as is, it answers `401`:

```python
from django_resaas.saas.core.utils.full_path import FullPath

FullPath.url(request, person.photo.url)                    # temporary
FullPath.url(request, entity.logo.url, temporary=False)    # permanent (e.g. an e-mail logo)
```

`FullPath.url()` needs the `request` for a relative URL (it builds the absolute URL from it) and
returns `None` without one.

> [!NOTE]
> If either the relevant `FILE_TOKEN.ENABLE_*` setting is off or `FILE_TOKEN.KEY` isn't
> configured, `FullPath.url()` returns `None` for that field rather than an unprotected URL —
> fails closed, never falls back to exposing the file. `FILE_TOKEN.KEY` has no default.

### Serving the file (web server)

The token is checked by Django (`FileAccessMiddleware`). A web server that serves `MEDIA_ROOT`
itself (an nginx `location /media/ { alias ...; }`) answers before Django and **skips the
check**: every file is then readable by whoever knows its URL. Send `/media/` to Django and let
nginx deliver the file only after Django authorised it:

```python
DJANGO_REST_AUTH = {
    "FILE_TOKEN": {
        "KEY": os.environ.get("URL_FILE_KEY"),
        # ...
        "X_ACCEL_REDIRECT": os.environ.get("FILE_X_ACCEL_REDIRECT"),  # e.g. "/protected-media/"
    },
}
```

```nginx
location /media/ {
    include proxy_params;
    proxy_pass http://127.0.0.1:8000;      # the Django upstream
}

location /protected-media/ {
    internal;                              # unreachable from outside
    alias /path/to/mediafiles/;            # MEDIA_ROOT
}
```

With `X_ACCEL_REDIRECT` set, a valid request is answered with an empty response carrying
`X-Accel-Redirect: /protected-media/<path>`, and nginx sends the file (type, `ETag`, ranges).
Without it (default `None`) the request goes on to whatever serves media in Django
(`static()` in `DEBUG`). Paths that leave `MEDIA_ROOT` (`..`) are refused with `401`.

Troubleshooting:

- **Images answer `401`.** The URL has no token, the token was issued for another path, or a
  temporary token expired (reload the record). Code that returns `file.url` without `FullPath`
  produces this.
- **`/protected-media/...` answers `404` from outside.** Expected: the location is `internal`.
- **A file answers `200` without a token.** The web server serves `MEDIA_ROOT` itself; fix the
  `/media/` location as above.

## Documents (`Document`)

`saas/models/document.py`: a document (type, number, dates, file) attached to any object
through `content_type` + `object_id` (e.g. `Person.documents`).

- **Tenant**: `entity` / `branch`, set by the server from the signed context
  (`BaseAPIView.perform_create`, `persons/{id}/add_document/`, the person registration
  service) — never from the body. `BaseAPIView` scopes every read and write by them, so
  another Entity's document is a `404`. A `Person` is global; its documents are not.
- **Unique number**: `(entity, tipo, numero)` — two Entities may hold the same number;
  a duplicate within one Entity is `400` on `numero`.
- **Target**: the object must exist and, when it belongs to a tenant (has `entity`), to the
  current Entity (`400` on `object_id` otherwise).
- `persons/match/` returns only the current Entity's documents of each candidate.
- Migration `django_resaas.0004_document_entity_scope` attributes existing documents from
  the object they describe when it has an Entity; the others stay without one and are
  visible to nobody (fail closed).

Tests: `saas/tests/test_document_tenant_isolation.py`, `saas/tests/test_document_api.py`.

## Upload paths

`file_path(instance, file_name, pasta="")` (`core/base/models.py`) is the framework's
`upload_to` helper — it generates a UUID filename (never the original name, avoiding collisions)
under `{entity_type_id}/{entity_id}/{instance_id}/{pasta}/{filename}`, so uploads are already
organized per tenant on disk:

```python
class Document(BaseModel):
    attachment = models.FileField(upload_to=file_path)
```

## PDF

`core/utils` provides the building blocks for generating PDFs and the codes commonly embedded in
them, on top of WeasyPrint:

- `PDF(template_path, request, doc=None, download=False, **context)` — renders a Django template
  (or a raw HTML string, if `template_path` doesn't end in `.html`) to a PDF `HttpResponse`.
  `download=True` sets `Content-Disposition: attachment`; otherwise the PDF is served inline.
- `make_qr_b64(text)` / `make_barcode_b64(value)` — QR code / Code128 barcode as a base64-encoded
  PNG, ready to embed directly in an HTML template's `<img src="data:image/png;base64,...">`.
- `png_bytes_to_b64(png_bytes)` — the shared base64-encoding helper the two functions above use.

`BaseAPIView`'s built-in PDF actions (per-record and list export, gated by the `pdf_<model>`/
`pdf_list_<model>` permissions — see [Schema 1.0 contract](../api/schema-contract.md#shape)) are
what most models use these through; an application only needs to supply its own template.
Application-specific layout belongs in the app's own templates — reuse the utilities above rather
than duplicating QR/barcode generation per app.
