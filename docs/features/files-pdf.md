# Files and PDF

## File field representation

A `FileField`/`ImageField` is never serialized as a raw path or URL string. `FileFieldsMixin`
(part of `BaseSerializer`) represents it as a small object instead:

```json
{
  "url": "https://.../media/....png?token=1699999999.abc123...",
  "name": "logo.png",
  "ext": "png",
  "kind": "image",
  "mime_type": "image/png",
  "size": 48213
}
```

`kind` is derived from the file extension (`image`, `pdf`, `video`, `audio`, or `file` as a
catch-all) — not from the actual file content.

## Protected URLs

Every file URL carries a `?token=` query parameter, generated by `FullPath` (HMAC-signed against
`FILE_TOKEN.KEY`) and validated by `FileAccessMiddleware` on any request under `settings.MEDIA_URL`
— see [Middleware](../architecture/middleware.md#fileaccessmiddleware-coremiddlewarefile_accesspy---enabled-by-default).
Without a valid token, direct access to an uploaded file is rejected with a `401`.

Two kinds of token:

- **Temporary** (the default for any field not listed in the serializer's
  `permanent_fields_files`) — time-limited, `FILE_TOKEN.TEMP_TTL` seconds (default `300`),
  gated by `FILE_TOKEN.ENABLE_TEMPORARY`.
- **Permanent** — for a field name explicitly listed in `permanent_fields_files` on the
  serializer, gated by `FILE_TOKEN.ENABLE_PERMANENT`.

```python
class DocumentSerializer(BaseSerializer):
    permanent_fields_files = ["attachment"]   # this field's URL never expires

    class Meta:
        model = Document
        fields = "__all__"
```

> [!NOTE]
> If either the relevant `FILE_TOKEN.ENABLE_*` setting is off or `FILE_TOKEN.KEY` isn't
> configured, `FullPath.url()` returns `None` for that field rather than an unprotected URL —
> fails closed, never falls back to exposing the file.

## Upload paths

`file_path(instance, file_name, pasta="")` (`core/base/models.py`) is the framework's
`upload_to` helper — it generates a UUID filename (never the original name, avoiding collisions)
under `{entity_type_id}/{entity_id}/{instance_id}/{pasta}/{filename}`, so uploads are already
organized per tenant on disk:

```python
class Document(BaseModel):
    attachment = models.FileField(upload_to=file_path)
```

## PDF

`core/utils` provides the building blocks for generating PDFs and the codes commonly embedded in
them, on top of WeasyPrint:

- `PDF(template_path, request, doc=None, download=False, **context)` — renders a Django template
  (or a raw HTML string, if `template_path` doesn't end in `.html`) to a PDF `HttpResponse`.
  `download=True` sets `Content-Disposition: attachment`; otherwise the PDF is served inline.
- `make_qr_b64(text)` / `make_barcode_b64(value)` — QR code / Code128 barcode as a base64-encoded
  PNG, ready to embed directly in an HTML template's `<img src="data:image/png;base64,...">`.
- `png_bytes_to_b64(png_bytes)` — the shared base64-encoding helper the two functions above use.

`BaseAPIView`'s built-in PDF actions (per-record and list export, gated by the `pdf_<model>`/
`pdf_list_<model>` permissions — see [Schema 1.0 contract](../api/schema-contract.md#shape)) are
what most models use these through; an application only needs to supply its own template.
Application-specific layout belongs in the app's own templates — reuse the utilities above rather
than duplicating QR/barcode generation per app.
